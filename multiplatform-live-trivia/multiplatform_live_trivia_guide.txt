MULTIPLATFORM LIVE TRIVIA
COMPLETE USER GUIDE
TikTok + Facebook Live + Social Stream Ninja
Local Python/FastAPI application

============================================================
1. WHAT THIS PROJECT DOES
============================================================

This application runs a local trivia game and accepts chat answers from
TikTok and Facebook.

Main flow:

    TikTok comments
          |
          v
    TikTok adapter
          |
          +------------------+
                             |
    Facebook comments       v
          |            Chat Queue
          v                 |
    Social Stream Ninja     v
          |             Trivia Engine
          |                 |
          +-----------------+
                            |
                            v
                     Web Dashboard
                            |
                            v
                       Leaderboard

Facebook no longer uses the Meta Graph API in this setup.

Facebook comments are captured by Social Stream Ninja and delivered to
the Python application through a WebSocket on Channel 4.

============================================================
5. SOCIAL STREAM NINJA
============================================================

Social Stream Ninja is the bridge between Facebook chat and this
Python application.

Official API documentation:

    https://github.com/steveseguin/social_stream/blob/main/api.md

Current Social Stream Ninja documentation says that a chat listener
should:

    1. Enable remote API control of the extension.
    2. Enable "Send chat messages to API server".
    3. Listen on WebSocket Channel 4.

The Python adapter connects to:

    wss://io.socialstream.ninja/join/SESSION_ID/4

Channel 4 is the chat-message channel.

============================================================
6. CREATE / OPEN YOUR SOCIAL STREAM NINJA SESSION
============================================================

Open:

    https://socialstream.ninja/

Open the Social Stream Ninja Dock.

A Dock URL looks like:

    https://socialstream.ninja/dock.html?session=XXXXXXXXXX

The value after:

    session=

is the Social Stream Ninja session ID.

Example:

    https://socialstream.ninja/dock.html?session=yZtdNe2iXn&v=3.50.25

The session ID in this example is:

    yZtdNe2iXn

Important:

Keep using the same session URL/session when possible.

If you create a new Social Stream Ninja session and its URL contains
a different session value, update config.json with the new value.

Do not assume that the session ID is the Facebook video ID. They are
completely different things.

============================================================
7. SOCIAL STREAM NINJA SETTINGS
============================================================

In Social Stream Ninja open:

    Global Settings
        >
    Mechanics

For this trivia application, make sure these are enabled:

    [x] Enable remote API control of extension

and:

    [x] Send chat messages to API server

The second setting is especially important.

The current Social Stream Ninja API documentation identifies
"Send chat messages to API server" as the setting required to receive
chat messages on Channel 4.

You do not need to enable unrelated API options just for the trivia
chat listener.

============================================================
13. WHAT TO DO IF THE DOCK SHOWS THE COMMENT BUT THE DASHBOARD DOES NOT
============================================================

This is an important troubleshooting case.

If:

    Social Stream Ninja Dock = comment visible

but:

    Trivia dashboard = no comment

then Facebook itself is NOT the problem.

The failure is somewhere after Social Stream Ninja capture.

Check these items in order:

1. Confirm:

       Facebook: CONNECTED

2. Confirm the Python app is using the same session ID shown in the
   Social Stream Ninja Dock URL.

3. Confirm:

       Send chat messages to API server

   is enabled.

4. Restart:

       python main.py

5. Post a NEW test comment.

6. Check the terminal running Python for connection/disconnection
   messages.

Do not immediately change facebook.py.

The connection can be established while message routing is still
incorrect, so testing Channel 4 is the correct next step.

============================================================
14. DIRECT CHANNEL 4 TEST
============================================================

Social Stream Ninja's official API documentation gives this WebSocket
pattern for a chat listener:

    wss://io.socialstream.ninja/join/SESSION_ID/4

Channel 4 is the channel used for chat messages when the appropriate
API setting is enabled.

A minimal independent Python test is:

    import asyncio
    import json
    import websockets

    SESSION_ID = "YOUR_SESSION_ID"

    async def test():
        uri = f"wss://io.socialstream.ninja/join/{SESSION_ID}/4"

        async with websockets.connect(uri) as ws:
            print("CONNECTED TO CHANNEL 4")

            async for raw in ws:
                print(raw)

    asyncio.run(test())

Run this only as a troubleshooting test, not as a replacement for
the production application.

If this test prints incoming JSON when a Facebook comment is posted,
Social Stream Ninja Channel 4 is working.

If the independent test receives the comment but the trivia app does
not, the problem is inside the application's Facebook adapter or
queue handling.

============================================================
15. MCQ QUESTIONS
============================================================

MCQ questions use:

    "type": "mcq"

and:

    "options": {
      "A": "London",
      "B": "Paris",
      "C": "Berlin",
      "D": "Madrid"
    }

Example question:

    {
      "question": "What is the capital of France?",
      "type": "mcq",
      "options": {
        "A": "London",
        "B": "Paris",
        "C": "Berlin",
        "D": "Madrid"
      },
      "answers": ["B"]
    }

The answer can also use the option text:

    "answers": ["Paris"]

The matcher is case-insensitive.

For the example above, a player can answer:

    B

or:

    b

and the option is treated as the same answer.

============================================================
16. IMPORTANT MCQ ANSWER RULE
============================================================

For a single-answer MCQ, keep the correct answer unambiguous.

Recommended:

    "answers": ["B"]

or:

    "answers": ["Paris"]

Do not intentionally list different correct options such as:

    "answers": ["A", "B"]

unless the question is designed to accept multiple correct choices.

18. 15-SECOND TIMER
============================================================

The current game configuration uses:

    "question_duration_sec": 15.0

The backend is the source of truth for the countdown.

The browser displays the server's:

    time_remaining

value.

This avoids the old problem where a browser timer could restart or
drift every time a WebSocket snapshot arrived.

The timer also has sound effects:

    web/sfx/tick.mp3
    web/sfx/end.mp3

The browser loads them from:

    /static/sfx/tick.mp3
    /static/sfx/end.mp3

The tick sound plays as the displayed countdown second changes.

The end sound plays when the question leaves ACTIVE and moves into
the ending/result phase.

21. LEADERBOARD
============================================================

The application writes:

    data/leaderboard.json

and:

    data/leaderboard.txt

The leaderboard is persisted at result/finished stages.

The application also initializes the leaderboard persistence when it
starts.

Current behavior is intentionally to clear the previous leaderboard
at program startup.

Therefore:

    Restart application
          =
    start a fresh leaderboard

After the game finishes, the final leaderboard remains available until
the application is restarted.

============================================================
23. RUNNING ON A SECOND DEVICE
============================================================

The default web server is:

    127.0.0.1

That means it is accessible only from the same computer.

If you want another device on the same network to open the dashboard,
the web server must listen on the computer's network interface rather
than only localhost.

Do not change this casually on a public/untrusted network.

For a private home/local network, use your computer's LAN IP and
configure the web server accordingly.

25. FACEBOOK DOES NOT USE GRAPH API NOW
============================================================

The current Facebook implementation is intentionally different from
the previous Meta Graph API approach.

Old approach:

    Python
       |
       v
    Meta Graph API
       |
       v
    Facebook

Current approach:

    Facebook
       |
       v
    Social Stream Ninja
       |
       v
    WebSocket Channel 4
       |
       v
    Python

Therefore you do not need:

    FACEBOOK_ACCESS_TOKEN

or:

    live_video_id

for the current Facebook adapter.

The Facebook config uses:

    session_id

============================================================
26. DO NOT CONFUSE THESE IDs
============================================================

There are several different identifiers.

A. Social Stream Ninja session ID

Example:

    yZtdNe2iXn

Found in:

    dock.html?session=yZtdNe2iXn

Used in:

    config.json

B. Facebook video/live ID

This belongs to Facebook.

It is NOT used as the Social Stream Ninja session ID.

C. Facebook URL

Example:

    https://www.facebook.com/Reuters/videos/...

This is a page/video URL.

It is NOT the value for:

    facebook.session_id

29. TROUBLESHOOTING CHECKLIST
============================================================

Problem:
    Facebook says DISABLED.

Check:
    "enabled": true

and:

    "session_id": "YOUR_SESSION_ID"

Problem:
    Facebook says DISCONNECTED.

Check:
    Social Stream Ninja is running.
    The session ID is correct.
    Internet connection is working.
    Restart python main.py.

Problem:
    Facebook says CONNECTED but no comments reach the game.

Check in this order:

    1. Comments visible in Social Stream Ninja Dock?
    2. "Send chat messages to API server" enabled?
    3. Correct session ID?
    4. Python connected to Channel 4?
    5. Restart main.py.
    6. Test with a NEW comment.

Problem:
    Comment appears in Social Stream Ninja but not dashboard.

This is the most important diagnostic distinction.

It means:

    Facebook -> Social Stream Ninja = WORKING

but:

    Social Stream Ninja -> Python = NOT YET VERIFIED/WORKING

Do not change Facebook settings that are already proven to work.
Test Channel 4 next.

Problem:
    Dashboard says TikTok CONNECTING.

Treat TikTok separately. Facebook can still work.

Problem:
    Timer appears to reset.

Check that the current web/app.js uses the backend
snap.time_remaining value as the source of truth.

Problem:
    No sound.

Check:

    web/sfx/tick.mp3
    web/sfx/end.mp3

and browser audio permissions.

Click START ROUND from the dashboard to provide a user interaction
that allows the browser to unlock audio playback.

Problem:
    Old leaderboard is gone.

This is expected after application startup with the current behavior.

31. THE MOST IMPORTANT CONCEPT
============================================================

There are three separate tests.

TEST 1:

    Facebook -> Social Stream Ninja

Proof:
    Comment appears in Social Stream Ninja Dock.

TEST 2:

    Social Stream Ninja -> Python

Proof:
    Python receives the comment from Channel 4.

TEST 3:

    Python -> Trivia Engine -> Dashboard

Proof:
    The comment appears in the application/queue and is processed
    as a trivia answer.

Do not treat a successful Test 1 as proof that Tests 2 and 3 work.
